# MDX 编写注意事项

在 Astro 项目中编写 `.mdx` 文件时，有几个常见陷阱会导致解析错误或渲染异常。编写前请务必阅读以下规则。

## 1. 不要使用 HTML 注释

**错误写法：**
```mdx
<!-- 这是注释 -->
```

**原因：** MDX 不支持 `<!-- -->` 形式的 HTML 注释。解析器会报错：
```
Unexpected character ! (U+0021) before name...
```
即使注释写在 SVG 或 JSX 元素内部，也会触发解析错误。

**替代方案：**
- MDX 注释：`{/* 这是注释 */}` （仅在 JSX 表达式上下文中有效）
- 直接删除无用注释，保持文件简洁

## 2. 不要在 MDX 中插入 `<script>` 标签内的代码

**错误写法：**
```mdx
<script>
  // 内联 JavaScript 代码
  const x = 1;
</script>
```

**原因：** MDX 解析器会尝试将 `<script>` 标签内部的内容作为 MDX/JSX 解析，其中的花括号、运算符等会引发解析问题。

**替代方案：**
- 在 Astro 组件中定义脚本，在 MDX 中 import 引入
- 使用 `is:inline` 等 Astro 指令（如果是 Astro 环境）
- 将脚本提取到独立的 `.js`/`.ts` 文件中导入

## 3. 不要随意换行——换行生成 `<p>` 元素

**行为：** 在 MDX 中，一个空行会创建新的段落（`<p>` 标签）。即使在 JSX 元素内部，换行也可能被 MDX 解析器解释为段落内容。

**错误示例：**
```mdx
<div>
  第一行

  第二行
</div>
```
上面的空行会在 div 内部生成两个 `<p>` 元素，可能破坏布局（例如引入意外的 margin/padding）。

**正确写法（连续内容不换行）：**
```mdx
<div>
  第一行
  第二行
</div>
```
或者使用显式的 `<p>` 标签来控制。

**注意事项：**
- 在复杂的 JSX 布局中，尽量保持内容紧凑，避免无意义的空行
- 如果需要间距，使用 CSS（style/class）控制，不要用空行撑高
- 在列表、表格等结构中，空行也可能导致非预期的解析结果

## 4. 其他常见陷阱

### 4.1 花括号 `{}` 的含义
在 MDX 中，`{}` 是 JSX 表达式，不是普通文本。如果需要显示字面量的花括号，需要转义或使用字符串：
```mdx
{/* 错误 */}
价格是 {100} 元

{/* 正确 */}
价格是 &#123;100&#125; 元
价格是 {'{100}'} 元
```

### 4.2 导入语句必须在顶部
`import` 语句应放在 frontmatter 之后、正文内容之前，且不能被任何内容打断。

### 4.3 组件命名
MDX 中使用的自定义组件必须以大写字母开头（React/JSX 规范）。

### 4.4 style 属性
MDX/JSX 中的 `style` 属性值必须是对象，不是字符串：
```mdx
{/* 错误 */}
<div style="color: red;">

{/* 正确 */}
<div style={{ color: 'red' }}>
```

## 快速检查清单

在保存 MDX 文件前，快速过一遍：

- [ ] 没有 `<!-- -->` HTML 注释
- [ ] 没有内联 `<script>` 标签
- [ ] JSX 布局内没有无意义的空行（避免意外 `<p>`）
- [ ] `style` 属性使用的是对象语法
- [ ] `import` 语句都在顶部
- [ ] 花括号用途正确（表达式 vs 文本）
